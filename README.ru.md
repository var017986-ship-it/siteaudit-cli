# SiteAudit

Небольшой CLI-чекер безопасности веб-сайтов на Python. Он объединяет ограниченный обход страниц на том же хосте, проверки HTTPS и заголовков, несколько проверок открытых служебных путей, а также безопасные тесты отражения ввода и признаков ошибок базы данных.

Это учебный проект и основа для дальнейшего развития, а не замена профессиональному пентесту или полноценным сканерам OWASP ZAP, Nuclei, Nikto и Wapiti. Чекер не обещает найти все уязвимости. Для каждой находки указывает URL, наблюдаемые признаки, серьёзность, уверенность и совет по исправлению.

## Используйте только с разрешения

Проверяйте только сайты, которыми владеете, или сайты, на проверку которых у вас есть явное разрешение. Чекер ограничивает запросы указанным хостом и глубиной обхода. Он не подбирает пароли, не отправляет формы POST, не загружает файлы и не пытается выполнять команды. Активные проверки используют безвредную строку и признаки ошибок через GET, а также HEAD и OPTIONS. Некоторые приложения меняют данные даже при GET-запросах, поэтому запускайте чекер только на целях, где допустимы такие особенности. Отражение строки и сообщение базы данных — признаки для ручной проверки, а не доказательство эксплуатации.

## Требования

- Python 3.11 или новее
- Сторонние Python-пакеты не нужны

## Установка

```powershell
python -m pip install -e .
```

## Запуск

```powershell
siteaudit https://example.com --output report.json
```

Или без установки команды:

```powershell
python -m siteaudit https://example.com --output report.json
```

Флаг `--help` показывает настройки скорости, глубины и ограничений обхода. По умолчанию запускаются ограниченные проверки путей и GET-параметров. Флаг `--passive` отключает эти адресные пробы и оставляет обход и анализ полученных ответов. Для локальных и частных IP нужен явный `--allow-private`.

Значения параметров URL в сохранённом отчёте скрываются. В отчёте всё ещё могут быть домен и технические сведения о сервере, поэтому обращайтесь с ним аккуратно.

## Что проверяется

- Наличие HTTPS, ошибки проверки TLS-сертификата, заголовки безопасности и флаги cookie.
- Страницы и GET-формы на том же домене с настраиваемыми пределами глубины и числа страниц.
- Небольшой список типовых служебных файлов и настроек веб-сервера. Для таких путей используется HEAD; содержимое потенциально секретных файлов не скачивается.
- До 24 ограниченных GET-проб по найденным параметрам и формам: безвредная строка для проверки отражения и одиночная кавычка для поиска характерных ошибок базы данных.
- JSON-отчёт с серьёзностью, уверенностью, признаками, адресом и советом по устранению.

Чекер не содержит большую базу шаблонов CVE из Nuclei, прокси и правила активного сканирования ZAP или экосистему плагинов W3AF. Он не может гарантировать, что конкретный GET-маршрут приложения не меняет состояние. Веб-приложения отличаются; важные результаты нужно проверять вручную.

## Разработка

В проекте только стандартная библиотека Python. Модули используют общий HTTP-клиент и формат находок, чтобы новые собственные проверки можно было добавлять отдельно.
