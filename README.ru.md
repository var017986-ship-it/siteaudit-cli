# SiteAudit

CLI-чекер безопасности веб-сайтов на Python. Один CLI объединяет ограниченный обход одного хоста, проверки HTTPS/заголовков/cookie, проверки служебных путей в духе Nikto, признаки проблем параметров в духе Wapiti, пассивные проверки ответов по мотивам ZAP, модульные проверки в духе W3AF и локальные буквальные JSON-шаблоны по мотивам Nuclei.

Это учебный проект и основа для дальнейшего развития, а не замена профессиональному пентесту или полноценным сканерам OWASP ZAP, Nuclei, Nikto и Wapiti. Чекер не обещает найти все уязвимости. Для каждой находки указывает URL, наблюдаемые признаки, серьёзность, уверенность и совет по исправлению.

## Используйте только с разрешения

Проверяйте только сайты, которыми владеете, или сайты, на проверку которых у вас есть явное разрешение. Чекер ограничивает запросы указанным хостом и глубиной обхода. Он не подбирает пароли, не загружает файлы и не пытается выполнять команды. POST-проверки выключены по умолчанию; флаг `--post-probes` отправит не более одного запроса с маркером в каждую из пяти найденных форм и может создать данные в приложении. GET-маршруты тоже иногда меняют данные, поэтому запускайте чекер только на целях, где допустимы такие особенности. Отражение строки и сообщение базы данных — признаки для ручной проверки, а не доказательство эксплуатации.

## Требования

- Python 3.11 или новее
- Сторонние Python-пакеты не нужны

## Установка

```powershell
python -m pip install -e .
```

## Запуск

```powershell
siteaudit https://example.com --output report.json
```

Чтобы дополнительно отправить безвредный маркер не более чем в пять найденных POST-форм (это может создать данные на сайте):

```powershell
siteaudit https://example.com --post-probes --output report.json
```

Отдельный флаг `--graphql-probe` проверяет, возвращает ли GraphQL endpoint имя типа запросов при introspection. Он отправляет до трёх фиксированных read-only POST-запросов на том же хосте, без cookies и авторизации; результат считается информационным:

```powershell
siteaudit https://example.com --graphql-probe --output report.json
```

Добавить проверенные локальные JSON-шаблоны можно через `--templates-file`; формат описан в [docs/custom-templates.md](docs/custom-templates.md).

Или без установки команды:

```powershell
python -m siteaudit https://example.com --output report.json
```

Флаг `--help` показывает настройки скорости, глубины и ограничений обхода. По умолчанию запускаются ограниченные шаблонные проверки, проверки путей и GET-параметров. Флаг `--passive` отключает эти адресные пробы и оставляет обход и анализ полученных ответов. Для локальных и частных IP нужен явный `--allow-private`.

Значения параметров URL в сохранённом отчёте скрываются. В отчёте всё ещё могут быть домен и технические сведения о сервере, поэтому обращайтесь с ним аккуратно.

## Что проверяется

- Наличие HTTPS, ошибки проверки TLS-сертификата, заголовки безопасности и флаги cookie.
- Страницы и GET-формы на том же домене с настраиваемыми пределами глубины и числа страниц.
- Ограниченный кэш ответов в памяти (до 100 ответов и 2 МБ) для пассивных проверок mixed content, слабого CSP, stack trace и CORS-заголовков.
- Небольшой список типовых служебных путей. Проверка использует HEAD без загрузки содержимого и сравнивает ответы со случайным несуществующим путём, чтобы отсеивать типовые soft-404 и SPA catch-all.
- До 24 ограниченных GET-проб по найденным параметрам и формам: безвредная строка для проверки отражения, одиночная кавычка для поиска характерных ошибок базы данных и проверка open redirect на параметрах перенаправления. По редиректу чекер не переходит.
- Небольшой модульный набор W3AF-подобных проверок: отражение произвольного CORS Origin с credentials и POST-формы без распознаваемого CSRF-поля. Формы только анализируются, запросы POST не отправляются этой проверкой.
- Опциональная проверка GraphQL introspection: один фиксированный read-only запрос максимум к трём endpoint-ам на том же хосте; схема не сохраняется, результат информационный.
- Локальные JSON-шаблоны с методами только GET/HEAD и буквальными проверками статуса, заголовков и ответа. Шаблоны не могут выполнять код или задавать произвольные payload-строки.
- Можно добавить до 27 своих проверенных JSON-шаблонов через `--templates-file` (всего не более 32 вместе с пятью встроенными).
- JSON-отчёт с серьёзностью, уверенностью, признаками, адресом, советом по устранению и ссылками на источники для шаблонных находок.

Встроенные шаблоны проверяют публичный индекс Go pprof, endpoint Spring Boot Actuator mappings, техническую Django 404-страницу при включённом debug-режиме и OpenAPI-спецификацию на двух распространённых адресах. Доступная API-документация отмечается как информационное наблюдение, поскольку часто она опубликована намеренно. Это проверки доступности диагностических поверхностей, а не общая база CVE.

Сверка реализованных возможностей и оставшихся пробелов: [FEATURES.md](FEATURES.md).

Небольшой локальный набор правил не совместим с большой базой шаблонов CVE из Nuclei и не заменяет её. Здесь также нет перехватывающего прокси и полного набора правил ZAP; в собственном реестре W3AF-подобных проверок пока два узких плагина, а не сотни. Чекер не может гарантировать, что конкретный GET- или явно включённый POST-маршрут приложения не меняет состояние. Веб-приложения отличаются; важные результаты нужно проверять вручную.

## Разработка

В проекте только стандартная библиотека Python. Модули используют общий HTTP-клиент и формат находок, чтобы новые собственные проверки можно было добавлять отдельно.
